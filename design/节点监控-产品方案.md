# 节点监控：macOS 服务器监控方案

此文件保留最初产品与视觉设想。用户已确认 Linux / Ubuntu 为主要目标，后续以 [完整开发方案 v2](节点监控-完整开发方案.md) 为准，其中更新了开源复用路线、默认 5 秒实时目标、低资源验收与部署结构。

日期：2026-10-28。当前交付为产品方案与视觉概念，效果图使用示例数据，尚未开发或连接真实服务器。

## 产品定位

做一个常驻 Mac 菜单栏的轻量应用，查看局域网和远程服务器的硬件负载、温度和连接状态。同一套数据提供三个入口：菜单栏速览、桌面实时挂件、完整监控台。

暂按 Linux / Ubuntu、NVIDIA GPU 服务器作为首版目标；Windows、AMD、NAS 专有接口按实际设备分阶段适配。

## 三个使用入口

| 入口 | 主要信息 | 交互 |
| --- | --- | --- |
| 菜单栏 | 选定服务器的 CPU / GPU 使用率、指定传感器温度、异常数量 | 自定义显示项目；点击展开；切换服务器 |
| 桌面挂件 | 单机 CPU / GPU、内存 / 显存、温度、小曲线和最后更新时间 | 拖动位置；小 / 中尺寸；透明度；锁定；可选置顶；多显示器位置记忆 |
| 完整窗口 | 多服务器列表、历史曲线、多 GPU、网络和磁盘、异常记录 | 按局域网 / 远程分组；查看 15 分钟 / 1 小时 / 24 小时；固定为挂件 |

桌面挂件采用 AppKit 无边框窗口或 NSPanel，实现持续刷新。WidgetKit 可作为后续低频摘要入口，其更新由系统调度，不作为秒级监控的实现基础。

## 指标范围与边界

| 类别 | 首版展示 | 支持边界 |
| --- | --- | --- |
| CPU | 总使用率、可选每核心使用率、负载、频率、温度 | 温度依赖目标系统暴露的传感器；保留封装 / 核心等标签 |
| GPU | 每张卡的计算使用率、温度、显存占用、功耗、风扇 | 先接 NVIDIA NVML；每个字段独立判断支持能力；有些卡没有风扇或不支持某项数据 |
| 内存 | 已用 / 总量、使用率、Swap | RAM 温度仅在存在可识别传感器时展示，不推算温度 |
| 磁盘 | 分区容量、读写速率 | SSD / HDD 温度和健康信息后续单独适配；读取权限取决于系统 |
| 网络 | 每网卡收发速率、连接延迟、掉线状态 | 带宽单位固定并可切换；避免把累计字节当成即时速率 |
| 设备 | 名称、系统、CPU / GPU 型号、运行时间 | 连接状态与各指标的数据新鲜度分别记录 |

没有设备、传感器不支持、权限不足、数据过期分别呈现；不以 0°C、0% 代替缺失数据。虚拟机和云主机可能不暴露宿主机物理温度。

## 数据采集与连接

```text
Linux / Ubuntu / GPU 服务器 ─┐
NAS / 其他已适配设备 ────────┼─ 只读采集端 ─ 加密连接 ─ Mac 数据中心
远程服务器 ──────────────────┘                         ├─ 菜单栏
                                                       ├─ 桌面挂件
                                                       └─ 完整窗口
```

- 每台服务器运行一个轻量采集端，Mac 通过配置的地址和独立凭证读取。仅知道 IP 地址并不足以获得远程温度；需要采集端、已有监控接口或获准的 SSH 访问。
- 局域网使用认证的 HTTPS / WebSocket 直连；远程首版优先通过已有 VPN 或 SSH 隧道连接，公网直连使用正确配置的 HTTPS 和独立认证。
- 无法从 Mac 直连且没有 VPN / 隧道时，后续提供采集端主动连接自建中转的模式。这会增加服务端部署与维护，不纳入最小首版。
- 已有 Prometheus / 其他监控接口的环境可后续增加适配器，避免要求重复安装采集程序。
- SSH 免常驻采集端模式可作为后续基础功能；只调用已安装的只读命令，温度和 GPU 覆盖依赖远端环境。

## 技术选择

| 模块 | 建议 |
| --- | --- |
| Mac 界面 | Swift + SwiftUI，目标 macOS 14+；MenuBarExtra 显示菜单栏摘要与展开面板 |
| 桌面挂件 | AppKit 窗口 / NSPanel + SwiftUI 内容；可设置桌面层或浮动层 |
| 趋势图 | Swift Charts |
| 服务器采集端 | Go 单程序，基础系统指标采用 gopsutil；GPU 接 NVIDIA NVML；温度优先使用带正确标签的系统传感器接口 |
| Linux 温度 | hwmon / libsensors；保留传感器名称、单位、采样时间和支持状态 |
| Windows 后续适配 | 系统性能接口 + LibreHardwareMonitor 等硬件适配层；实际驱动和权限需求按机器核验 |
| 数据连接 | URLSession + HTTPS / WebSocket；断线退避重连；读写超时 |
| 历史与设置 | Mac 本地 SQLite 存指标与事件；Keychain 存凭证 |

首版无需公共云账号或统一云平台。Mac 关闭或休眠时，Mac 本地采集历史会有缺口；如果要全天历史和告警，需在常在线服务器保存历史与执行规则，后续单独增加。

## 刷新、状态与告警

- 设计目标：前台或挂件可见时每 2 秒采样；后台可配置 5–10 秒。图表显示最近窗口，并按实际数据降采样。具体资源占用与延迟需在真实硬件测量。
- 数据包含主机 ID、设备 ID、指标来源、单位、采样时间、接收时间和支持状态。多 GPU 按稳定设备 ID 区分。
- 示例规则：连续多次采样失败或超过 15 秒没有新数据时标记过期；保留上次读数并显示最后更新时间，趋势图用断点表示缺口。
- 温度、GPU 持续高负载、内存不足、磁盘将满和服务器离线可设置系统通知。阈值按设备配置，加入持续时间、恢复阈值和冷却期，防止通知反复跳变。
- 首版通知由 Mac 应用执行；Mac 休眠时不保证告警可达。

## 首版范围与开发顺序

1. 接通一台真实 Linux / NVIDIA 服务器，验证 CPU、GPU、内存、显存和温度来源；不支持的字段正常缺省。
2. 完成多机列表、菜单栏速览、桌面挂件、完整窗口和刷新 / 重连状态。
3. 增加本地 24 小时曲线、阈值通知、设置持久化和凭证管理。
4. 根据实际机器增加 Windows / AMD / NAS、多 GPU 细节和全天历史服务。

验收重点：与服务器原生工具的同时间窗口读数对照；拔网与重连；无 GPU / 无传感器 / 权限不足；Mac 睡眠唤醒；多屏位置恢复。图像或界面能渲染不代表监控已接通。

## 视觉方向

- 菜单栏：浅色毛玻璃面板，强调一眼可读的数字。
- 桌面挂件：深色半透明卡片，支持单机与多个不同尺寸组合；数据过期时变暗并显示时间。
- 完整窗口：深色专业监控台，左侧机器分组，右侧指标卡与趋势曲线。
- 使用蓝色表示 CPU、琥珀色表示 GPU、青色表示内存、紫色表示显存；告警同时使用文字 / 图标，不能只靠颜色。
- 效果图是排版与交互方向参考，具体字体、系统材质、窗口层级以及不同屏幕上的效果需在原生实现时验证。
