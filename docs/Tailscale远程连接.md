# 内置 Tailscale 远程连接

当 Ubuntu 服务器在局域网、Mac 在其他网络时，节点监控可使用内置的 Tailscale 私有网络。**Mac 和服务器都不必单独安装 Tailscale 客户端**：Mac 应用内含网络组件，Linux 采集端含同一网络能力。两端首次各自授权，之后通常会记住登录；账户或密钥过期、策略要求重新授权时需再次登录。

此功能需要新的 Mac 应用和 Linux 采集端；已发布的 v0.1.0 不包含。已在实际 Ubuntu 与 Mac 上验证远程连接及硬件读数：Mac 切换到手机蜂窝热点后，连续收到服务器的实时数据。实际连接仍受双方网络和访问规则影响。

## 连接方式和安全边界

- **局域网连接**：只使用配置的内网地址，不将该服务器的请求发到 Tailscale。没有远程服务器或打开远程设置时，Mac 内置网络组件会停止；若仍有其他远程服务器在监控，则组件继续运行。
- **远程连接**：只使用已填写的 Tailscale IP 或完整的 `.ts.net` 设备名，不自动回退到局域网。请求仅通过内置的 Tailscale 用户态网络发送；不会创建系统 VPN 或修改全机路由。
- 服务器上的额外监听只存在于嵌入式 Tailscale 节点，仍需采集端访问令牌和网络策略许可，不向公网开放，也不作为其他本机服务的代理。两端 Tailscale 连接提供端到端加密。该模式不需要启用 Tailscale Serve 或申请 HTTPS 证书；如果服务器已有 Serve HTTPS 地址，也可填写其 `.ts.net` HTTPS 地址。
- 两端需加入同一 tailnet 或获得设备共享许可；网络管理员可能需要批准设备，并允许 Mac 节点访问服务器节点的监控端口。不同网络、防火墙或中继状况可能影响连接。

## 1. 准备 Ubuntu 采集端

将新版 `nodemon-agent-linux-amd64.tar.gz` 或 `nodemon-agent-linux-arm64.tar.gz` 解压到服务器的项目目录。首次设置需要能通过局域网、SSH 或服务器控制台访问该机器。保留原有 `data/agent.token`；若正在更新一个已有服务，应记录它原来的启动参数，在适当时间手动更新，避免同时运行两个采集端或覆盖已有数据。

在服务器项目目录的**交互式终端**运行：

```bash
./nodemon-agent --tailscale-login --tailscale-dir ./data/tailscale-agent
```

终端会显示临时授权链接。自行在浏览器打开并登录自己的 Tailscale 账号；不要分享链接，也不要把它写进日志或聊天。需要设备审批时按管理员提示完成。授权完成后，终端显示服务器的 Tailscale IPv4 地址；记下它供 Mac 使用。命令结束后节点会暂时离线，启动采集端后重新上线。授权链接不会由采集端写入服务日志或文件。

授权状态保存在服务器项目目录的 `data/tailscale-agent/`。这是私密设备身份，请像密码一样保护，不要提交或分享。持久状态只应被一个采集进程使用；重新授权时先停掉正在使用此目录的采集端。两端不需要使用相同的本机用户名，但要使用同一网络或设备共享授权。

## 2. 启动带远程能力的采集端

只允许本机或 Tailscale 访问监控接口：

```bash
./nodemon-agent --listen 127.0.0.1:9274 --token-file ./data/agent.token \
  --tailscale-listen :9274 --tailscale-dir ./data/tailscale-agent
```

如果还需要原有局域网直连，只在可信局域网中使用下面的方式：

```bash
./nodemon-agent --listen 0.0.0.0:9274 --allow-http-lan --token-file ./data/agent.token \
  --tailscale-listen :9274 --tailscale-dir ./data/tailscale-agent
```

两种监听使用同一份只读快照和令牌。不要把局域网的明文端口映射到公网。采集端退出后服务器远程节点离线；如需重启后继续运行，请在确认现有服务配置后自行修改或配置 systemd。程序不会自动安装服务、修改防火墙或路由。

## 3. Mac 连接

1. 打开新版节点监控，添加或编辑服务器，选择“远程连接”。
2. 在“这台 Mac”点击“登录并授权”，浏览器打开 Tailscale 授权页面。使用与服务器同一个网络的账号登录并授权本程序；即使 Mac 上已有独立 Tailscale，也需要为本程序的独立设备身份授权。
3. 回到应用等待状态变成“本机已授权”。如果网络需要管理员批准设备，完成批准后刷新状态。
4. 填写服务器的 Tailscale IP，例如 `100.64.1.2:9274`，或完整的设备名 `server.example.ts.net:9274`。这是示例，不代表实际地址。填写服务器 `data/agent.token` 的完整内容并保存。
5. 先确认应用显示实时读数，再通过手机热点等不同网络测试。只有“Mac 已授权”不能证明服务器可达。

切换到“局域网连接”后填写服务器的内网地址。两种地址分别保存，当前需**手动切换**，不会自动判断 Wi-Fi。若所有服务器都使用局域网模式且没有打开远程设置，Mac 会停止内置远程组件。

## 4. 资源和删除

选择远程连接时 Mac 多一个内置网络进程，服务器采集端也会运行网络栈；具体 CPU、内存和流量以实际环境测量为准。仅使用局域网时不会启动 Mac 的远程进程，服务器不传入 `--tailscale-listen` 时也不会启动远程网络。

Mac 的 Tailscale 身份位于项目目录 `data/mac/tailscale/`，服务器位于 `data/tailscale-agent/`；不要提交、截图或分享。磁盘格式可能不支持可靠的 Unix 文件权限，例如可移动的 ExFAT 磁盘；应确保磁盘本身受保护，必要时使用加密磁盘。删除这些目录会丢失登录状态；需要时在 Tailscale 管理界面另行移除对应设备。
