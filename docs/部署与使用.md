# 部署与使用

## 1. 选择服务器版本

- `uname -m` 为 `x86_64`：使用 `dist/nodemon-agent-linux-amd64.tar.gz`。
- `uname -m` 为 `aarch64`：使用 `dist/nodemon-agent-linux-arm64.tar.gz`。

将发行包复制到你有权限的 Linux 服务器，解压到独立文件夹，例如 `~/nodemon`。采集端为静态二进制，不需要 Docker、Go、Python 或 Node.js。

本次已实测 Ubuntu 26.04.1 x86_64、双 NVIDIA；Ubuntu 22.04 / 24.04 和 Linux ARM64 是待验证目标。温度和显卡指标取决于主板、内核驱动、GPU 驱动与账号权限；云主机可能完全没有物理温度。

## 2. 通过 SSH 隧道连接（推荐用于远程网络）

前提是 Mac 能访问服务器的 SSH 入口。服务器只在局域网且没有公网入口时，可先配置 [Tailscale 远程连接](Tailscale远程连接.md)。

在服务器采集端文件夹运行：

```bash
chmod +x nodemon-agent
./nodemon-agent --listen 127.0.0.1:9274 --token-file ./data/agent.token
```

首次运行自动创建随机令牌，文件权限 0600。日志只提示状态，不打印令牌。

在 Mac 的终端建立隧道，将占位用户名和服务器地址替换为自己的值：

```bash
ssh -N -L 9274:127.0.0.1:9274 your-user@your-server
```

在 Mac 应用选择“添加服务器”：名称自定；地址 `http://127.0.0.1:9274`；访问令牌填写服务器 `data/agent.token` 中的完整内容。令牌只通过私密终端读取并复制，不要放到聊天、截图、命令参数或公开文档里。监控完成后退出应用和隧道终端即可。

多台主机使用不同本地端口，例如 `-L 9275:127.0.0.1:9274` 对应 Mac 地址 `http://127.0.0.1:9275`。

## 3. 可信局域网直接连接

只在你信任的私有网络中显式允许明文连接：

```bash
./nodemon-agent --listen 0.0.0.0:9274 --allow-http-lan --token-file ./data/agent.token
```

Mac 地址填写 `http://服务器的局域网IP:9274`，勾选“允许明文 HTTP（仅可信局域网或隧道）”。令牌认证仍然必需。不要将这个明文端口映射到公网。

应用不会自动修改防火墙、端口映射或路由。若不能连接，检查 IP、服务监听地址与服务器自己的网络策略。

## 4. HTTPS 直连

已有域名及受信任的 TLS 证书时：

```bash
./nodemon-agent --listen 0.0.0.0:9274 --token-file ./data/agent.token \
  --tls-cert ./certs/fullchain.pem --tls-key ./certs/privkey.pem
```

Mac 填写 `https://你的证书域名:9274`。程序使用系统 TLS 校验，不跳过证书验证；自签证书应由管理员通过系统信任机制管理，或使用 SSH 隧道。没有实现网页跳转登录，API 重定向会拒绝，避免转发令牌。

## 5. GPU 与温度

NVIDIA 需要服务器已经安装正确驱动，并允许当前账号运行 `nvidia-smi`。程序不会安装驱动。一次查询获取每张卡的 UUID、型号、使用率、温度、显存、功耗、风扇；设备不支持的项留空。

```bash
./nodemon-agent --token-file ./data/agent.token --gpu-interval 30s
./nodemon-agent --token-file ./data/agent.token --no-gpu
```

CPU / 内存 / 网络等基础间隔由 `--interval 5s` 控制，最短 2 秒；GPU 间隔必须不小于基础间隔。容量查询每 30 秒执行。

CPU 温度识别 `coretemp`、`k10temp`、`zenpower` 或明确 CPU 标签。不会将主板任意 `temp1` 当成 CPU。传感器明细保留原标签与来源。

AMD / Intel GPU 为基础 sysfs 支持，尚未经实机验证；Intel 使用率、共享显存、部分 AMD 字段可能不可用。本版没有 NVML / Intel 专有驱动 / Jetson 适配。

## 6. 常驻服务（手动、可选）

先以前台方式确认读数和连接正常，再使用 `deploy/nodemon-agent-user.service` 用户服务模板。模板假设采集端目录为 `~/nodemon`，并保持仅监听本机，以便配合 SSH 隧道。

```bash
mkdir -p ~/.config/systemd/user
cp nodemon-agent-user.service ~/.config/systemd/user/nodemon-agent.service
systemctl --user daemon-reload
systemctl --user enable --now nodemon-agent.service
systemctl --user status nodemon-agent.service
```

这些命令仅作为供你在服务器执行的说明，本次开发不会自动运行。用户服务通常受用户登录会话影响；需要退出登录后仍全天运行时，由管理员配置系统服务或 linger。本项目另提供普通服务账号的系统服务模板，不能直接套用尚未创建的账号和目录。

## 7. Mac 菜单栏与挂件

双击项目内 `build/节点监控.app`，关闭监控台后菜单栏仍保留。菜单栏显示当前选择主机的摘要；固定到桌面可让多台主机同时显示。拖动挂件标题可移动位置；右键挂件可以切换尺寸、置顶、锁定；锁定后在“设置 → 挂件”解锁。

“设置 → 通用”可修改菜单栏指标、外观、节能模式与历史保留天数。“设置 → 提醒”可调整阈值和持续时间；仅在点击启用通知后才申请 macOS 通知权限。

应用激活时，`⌘0` 打开监控台，`⌘1` 展开菜单栏面板，`⌘,` 打开设置。macOS 15 及以上首次访问局域网时可能要求授权；若提示网络不可用，检查“系统设置 → 隐私与安全性 → 本地网络”中的节点监控权限。

所有显示入口共用数据。刷新按钮会重新请求缓存；它不会强制服务器额外执行一次硬件采集。部分主机失败会保留旧值并标记，其他主机继续更新。

## 8. 更新、备份与删除

更新前退出 Mac 程序、停止 Linux 采集端，用新版本替换程序文件，保留 `data/`。配置与数据库有版本检查，不兼容时停止并保留原文件。

退出 Mac 应用后备份整个 `data/`（含 SQLite 文件）。目录有私密访问令牌，按密码文件对待。Mac 退出或休眠期间不采集历史，曲线不会补造缺失读数。

Linux 卸载用户服务：

```bash
systemctl --user disable --now nodemon-agent.service
rm ~/.config/systemd/user/nodemon-agent.service
systemctl --user daemon-reload
```

然后自行删除服务器上的采集端文件夹。Mac 端退出应用后删除项目文件夹；无自动安装的登录项、守护进程或 Keychain 项。操作系统可能自行管理近期项目、通知授权等系统元数据。
