# 首版实现范围与协议

## 实施决定

首版包括 Mac 客户端和 Linux 采集端，运行文件与数据保存在各自的项目目录。

当前采用完整方案中的 B 路线：自有 Go Agent → 原生 Mac，共两个常驻程序。原因是首版需要精确控制采集频率与 GPU 查询、减少部署组件，并提供可独立删除的交付。A 路线的 Beszel Agent + Hub 仍是调研备选；本版直接选择 B 开发，未执行 Beszel 的 Linux 实机评估或性能比较。随后已在用户提供的 Ubuntu 26.04.1、双 NVIDIA 主机上验证本项目采集端和 Mac 直连。

与完整长期方案的范围差异：

- 本版无集中 Hub，退出 Mac 后不持续保存全天历史。
- NVIDIA 使用有限频率的 nvidia-smi；NVML 未实现。
- 未做自动发现、开机自启、远程命令、自动更新、Apple Developer ID 公证、Intel Mac 打包。
- 原方案的 3–5 台实机性能、能耗、GPU 空闲功耗验收仍待真实硬件执行。
- 便携模式将令牌保存为项目内受限文件，请求权限 0600；ExFAT 按卷挂载权限执行，本次检查确认其他用户无读写权限。不使用系统 Keychain，便于整体移除。请将项目目录视为含私密配置的目录。

## 文件边界

源码和构建产物全部在项目内。使用系统自带 Swift / Clang / SQLite / AppKit。官方 Go 工具链下载到 `.tools/go`；Go 和 Swift 缓存重定向到 `.cache` / `.build`。ExFAT 链接兼容层仅作用于项目内复制的 Go 链接器，详见 README 和 `Tools/linker-msync.c`；不进入发行程序，不修改官方原始工具链或系统设置。远端程序和运行数据保存在用户选择的独立目录中；不会自动修改全局 Go、系统网络、GPU 驱动、systemd 服务或登录项。

## HTTP 接口

- `GET /health`：仅返回服务就绪信息，不包含机器与指标。
- `GET /v1/snapshot`：需要 `Authorization: Bearer <token>`，只读、无控制命令、无修改 API。
- JSON `schemaVersion` 当前为 `1`，`agentVersion` 为采集程序版本。未知版本被客户端拒绝。
- 时间为 UTC RFC3339 / ISO8601；`sampledAt` 是采样时间，客户端另记接收时间；各 GPU 有独立采样时间。
- 使用率为 0–100、容量为 byte、速率为 byte/s、温度为 °C；不能采集的数值为 `null`，不是 `0`。
- CPU 初次读取需要两次计数器差值，第一份样本使用率为空并标记 warming_up。
- `cpu.packages` 是向后兼容的可选数组，每项包含 `id`、`packageID`、`name`、`logicalCores`、`usagePercent`、`temperatureCelsius`。启动时缓存 `/proc/cpuinfo` 的物理插槽与线程映射，各插槽复用一次 `/proc/stat` 读取并独立计算计数器差；不按线程数猜测 CPU 数量。逐颗温度仅在 coretemp 的 Package id 能明确对应时提供。首次采样、计数器复位或缺失均为空值。
- 菜单栏、面板、挂件和监控台使用 `cpu.packages` 与 `gpus` 的逐设备读数；两张显卡分别显示显存。GPU 缓存过期后保留设备标识，当前读数显示缺失。旧 Agent 没有 packages 时退回明确标注的整机 CPU。历史和告警继续使用整机 CPU 与最高 GPU 汇总，未新增逐插槽历史存储。
- 内存已用为总量减 MemAvailable；Swap 单独列出。磁盘已用包含文件系统保留差异，可用空间采用 f_bavail。
- 网络摘要优先汇总物理网卡；没有物理网卡时排除常见容器接口后汇总虚拟网卡。明细保留所有非 loopback 接口。复杂 bond、隧道、容器网络应以明细核对。
- 磁盘吞吐汇总底层块设备，排除分区、loop、ram 和有 slaves 的上层设备，避免常见叠加重复。
- 采集器不遍历进程列表，不执行通用远程命令。唯一外部指标命令为有超时和输出上限的 nvidia-smi。
- 客户端禁用重定向、Cookie 和磁盘 HTTP 缓存，限制响应 1 MiB，默认校验系统 TLS。

## 历史和提醒

SQLite 以“主机 ID + 采样时间”为主键，同一缓存样本只记一次。历史读取最多约 240 个时间桶，图表在明显中断处分段。背景低频的缺少样本不自动填充为零。按 1 / 7 / 30 天保留，每小时清理一次过期记录。

温度和高占用需在连续观察中超过阈值后记录事件，触发后使用 5 单位恢复迟滞与 5 分钟通知冷却；触发前回落到阈值以下会重新计时。相同采样时间不重复累积持续时间；采样间距超过当前客户端轮询间隔或服务端采样间隔的三倍（最少 15 秒）后重新计时。低频轮询无法判断两个观察点之间的瞬时波动。离线是采集端不可读取，不代表服务器关机。系统通知只能在 Mac 应用运行且有权限时发出。

## 实机与后续验收

本次已经验证 Ubuntu 26.04.1、普通账号、双 NVIDIA、真实 API、Mac 界面与短时资源占用。仍需补测 Ubuntu 22.04 / 24.04、Linux ARM64、AMD / Intel、驱动缺失、实际断网和服务器重启、长期内存与数据库增长、GPU 空闲功耗。没有暴露的物理传感器显示未提供。性能目标与实测分开，不把模拟服务或短时结果推算为长期能耗结论。
