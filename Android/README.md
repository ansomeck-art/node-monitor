# Android 监控客户端

## 0.3.1 挂件样式库与直接添加

在首页右上角的四格图标、首页“添加桌面挂件”、主机详情或设置的“主屏挂件”进入原生样式库。六类挂件均展示完整预览，顶部选择设备；点预览或“添加到桌面”直接发起 Android 标准添加请求，不再先经过主机文字列表和说明弹窗。设备数据存在时优先使用真实快照；缺少数据与宽卡告警 / 离线展示明确标为“样式示例”。

系统桌面仍决定是否显示确认和实际摆放。`requestPinAppWidget` 返回 `true` 只表示请求已发出；新版本等系统成功回调，并核对新挂件 ID、provider 和实例注册后才显示“已添加”及绑定所选主机。20 秒没有回调会显示“桌面尚未确认添加”，可以重试、打开标准应用信息页或查看桌面；随后收到有效回调仍可完成添加。不使用小米私有广播或绕过系统确认。

小米的“安卓小部件”可能位于系统挂件中心的较深入口。此版本保留所有既有 provider 类名和实例，且在挂件名称中加入“节点监控”前缀，方便搜索。AOSP Android 8.0 的真实桌面选择器和标准添加确认已验证；小米具体机型和系统版本仍需在手机上验证。

样式库功能从 `0.3.1-widget-gallery-dev` / versionCode `4` 起提供。当前后台刷新开发版为 `0.3.2-widget-live-dev` / versionCode `5`，沿用 `cn.nodemon.serverdeck.preview` 和同一本地签名，可覆盖安装保留主机与挂件。已构建的后台刷新包名为 `NodeMonitor-ServerDeck-widget-live-arm64.apk`；从源码构建时可使用 `-Output` 指定输出路径。

## 桌面实时刷新（0.3.2 开发版）

桌面挂件新增默认开启的“桌面实时刷新”：已有挂件时，打开 App 或从样式库完成添加，会启动带常驻通知的前台服务；App 退到后台后，约每 15 秒读取所选主机并更新挂件。全局汇总挂件需要全部主机数据，其余只轮询已绑定的主机。它与前台轮询共享同一主机锁，避免并发请求；最多三个工作线程，同一批未完成时不叠加下一批。手机断网时不把缺少观察记成服务器失败，恢复连接后重新观察告警持续时间。

样式库和设置页均可开启或暂停。通知内“停止实时刷新”也会关闭保存的开关；移除全部挂件会停止服务。暂停后保留 Android 系统定时更新，不再承诺 15 秒。常驻状态通知与告警通知是不同用途。

小米若在后台停止刷新，可以从样式库的“小米省电 / 通知设置”打开应用信息，将省电策略设为“无限制”；若系统提供后台自启动选项，可允许本应用。系统强行停止后需要重新打开 App；深度休眠、断网或厂商后台限制仍可能推迟刷新。应用不申请唤醒锁或精确闹钟来维持频率，也不会自动修改手机电池白名单。

此服务使用 Android `connectedDevice` 类型，实际用途为通过网络持续读取用户选择的外部电脑；声明 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE` 和正常权限 `CHANGE_NETWORK_STATE`。没有调用更改系统网络配置的 API。实现遵循 [Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types) 与 [后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)，只从可见页面或明确允许的用户动作请求启动；拒绝时提示重新打开应用，而不是绕过限制。

## ServerDeck 界面与监控功能（0.3 开发版）

按明暗两套参考稿重做原生 Android 界面：杏绿色、圆角卡片、四格概览、细进度条、设备 / 告警 / 设置底栏。保留系统状态栏，不添加顶部黑色气泡。设备详情分为硬件概览、存储与网络、趋势与进程，方便直接切换。

- 数值、进度条平滑变化，在线圆点呼吸，曲线末段随采样过渡，卡片与按钮有轻微按压反馈，换页淡入。遵循系统动画开关，退出前台停止前台轮询。
- 主机列表支持全部 / 告警 / 离线过滤；最近一小时 CPU 曲线、过去 24 小时采集成功率、CPU 峰值和告警 / 恢复摘要均来自本地实际记录。
- SQLite 去重保存采样、最近快照和告警。趋势支持 15 分钟、1 / 6 / 24 小时，拖动查看读数。CPU 曲线表示整机平均，另绘内存；中断处留空，不补造样本。历史可保留 1 / 7 / 30 天。
- CPU、内存、逐 GPU 温度、逐挂载磁盘占用告警需连续观察超过阈值 1 分钟，5 单位恢复迟滞。GPU 使用自身采样时间，重复、缺失或间隔过长的样本不增加持续时间。离线同时满足失败次数和时长条件。告警可搜索、筛选，保存严重程度及恢复记录。停用规则会关闭对应事件并标记“已关闭”。
- 前台刷新可设 5 / 10 / 15 / 30 秒，不改变服务器采样间隔。后台检查是可选 Android JobScheduler 任务，最短 15 分钟，系统省电策略可能继续延迟。它不提供后台每 5 秒的持续监控，断网和休眠期间不会补造历史或告警。
- 系统通知默认关闭，由用户开启并授予权限；支持严重 / 严重与警告、跨午夜静默时段。同一事件只在新建或升级为严重时通知，恢复后再次触发会形成新事件。这是本机通知，没有云端推送服务。
- 请求耗时是手机读取快照的总耗时，包含服务器响应时间；不标成 ping 或网络抖动。接口丢包率来自新版 Linux Agent 的网卡计数器，不代表端到端网络丢包。未提供的指标显示 `—`。

新版 Linux 采集端增加 `memory.cachedBytes`、`network.dropPercent`，并可在原有启动命令中追加：

```bash
--processes --services docker,nginx,tailscaled
```

`--processes` 读取 `/proc/<pid>/stat`，只传 Top 5 的名称、PID、CPU 和常驻内存，不读取命令行或环境变量。CPU 按整机总计算能力归一化，首次采样与 PID 复用时不推测占用。`--services` 限 16 个合法 systemd 服务名，每 30 秒通过有 1.5 秒超时与 64 KiB 输出上限的只读 `systemctl show` 查询。未安装 / 无法读取和已停止分开显示。这两项目前仅支持 Linux，需更新服务器采集端并显式开启。

### Windows 上构建 Android

准备 JDK 17、Android SDK platform 36 和 build-tools 36.0.0；`libnodemon.so` 由原有 `build-android.sh` 构建。本次 Java / 界面更新不修改内置 Tailscale 的 JNI 接口，也可复用同仓库现有发行版的未修改 ARM64 桥接库。

```powershell
.\scripts\build-android.ps1 -JavaHome '你的 JDK 路径' -AndroidSdk '你的 SDK 路径' `
  -ApplicationId cn.nodemon.serverdeck.preview -NativeLibrary '你的 libnodemon.so 路径'
```

默认输出 `build/android/NodeMonitor-ServerDeck-arm64.apk`。独立包名可与现有版本并存，配置需重新添加。开发签名保存在项目忽略目录 `.tools/android-signing/`，仅供本地测试。保留这把密钥可续装同一包名的本地构建；它无法更新使用其他密钥签名的旧版。`-WithoutNativeForTests` 仅用于模拟器直连 UI 测试，该包不能使用 Tailscale，不应作为手机交付包。

## 连接与挂件使用

开发版支持 Android 8.0 及以上的 64 位 ARM 手机，连接现有 Ubuntu 和 Windows 采集端。可添加设备速览、全局汇总、状态全景、控制面板、矩形配件和圆形配件六类挂件；中号状态卡自动显示正常、警告、离线三种状态，覆盖参考图的八种版本。每个单设备挂件可以绑定不同主机，添加时可选择，支持的桌面也可通过重新配置更换主机。实际格数、可调整尺寸和锁屏支持由桌面决定。主机详情中的“添加桌面挂件”可选择样式；如果系统没有弹窗，长按桌面空白处进入小部件列表。小米桌面通常要在小部件搜索页选择底部的“安卓小部件”。

挂件的在线状态点轻呼吸，玻璃表面有细微光泽扫动，圆形配件有环绕光点；圆弧长度和百分比始终代表真实采样，不随装饰动画改变。动效由桌面播放，不会为每帧请求服务器，遵循系统动画开关；熄屏和省电策略可能暂停动画。Android 12+ 使用系统壁纸生成的中性色作为半透明背景底色，杏绿色保持统一，明暗跟随系统。开启桌面实时刷新时约每 15 秒更新，并显示常驻通知；关闭后桌面定时更新约每 30 分钟，由系统决定实际时间。应用前台刷新或大面板“刷新”也会请求更新。点击挂件打开对应主机，全局汇总打开设备列表。大面板“静音 30 分钟”只暂缓该主机系统通知，告警仍保存，可点击恢复通知。缓存过期显示上次采样，不据此断定服务器离线。

点击添加主机，选择“登录 Tailscale，自动查找”，登录与服务器相同的 Tailscale 账号，返回应用后选择已发现的监控服务。自动查找最多检查该网络里的 32 台设备的默认端口 9274；服务器需要运行采集端并启用其 Tailscale 监听。若服务器开启下文的账号认证，无需填写地址和采集端令牌；旧服务器仍要求令牌，可以升级服务器或在选择时填写一次。使用非默认端口或找不到设备时可选择手动添加。也可以同时保存局域网地址和 Tailscale 地址，此时主机详情会提供切换按钮。局域网明文 HTTP 必须显式勾选，且只接受私有 IP；HTTPS 使用系统证书验证。令牌由 Android Keystore 加密并放在应用私有存储中，禁用应用备份。内置 Tailscale 使用用户态连接，无需单独安装 Tailscale，也不会更改系统 VPN 或路由。

服务器的免令牌连接是可选功能：在已有 Tailscale 监听参数的基础上增加 `--tailscale-owner-auth`。启用后，同一 Tailscale 用户拥有且网络规则允许访问的非标签设备，可通过该 Tailscale 监听读取监控快照；共享或带标签的设备仍需令牌。普通局域网监听始终要求令牌。启用前应确认希望给予该账号下这些设备读取权限；不加此参数时保持原来的令牌认证。

`build/android/NodeMonitor-development-arm64.apk` 为本地开发版；构建时使用一次性的临时签名，重新构建后需要先卸载旧版才能安装，卸载会删除应用配置。单独包名的测试版可以与旧版并存，但它的挂件和登录配置属于该测试版；卸载测试版也会移除其挂件和配置。正式发布前应另行设置安全管理的稳定签名，并在实体手机上验证续装、前后台更新、电池优化和各品牌桌面挂件。

macOS 构建：已安装 Android SDK 36、build-tools 36 和 Java 17，Android NDK r28c 放在项目 `.tools/android/` 后运行 `scripts/build-android.sh`。构建缓存和输出均位于项目文件夹。该脚本只生成开发 APK，不申请发布证书，不上传任何数据。
